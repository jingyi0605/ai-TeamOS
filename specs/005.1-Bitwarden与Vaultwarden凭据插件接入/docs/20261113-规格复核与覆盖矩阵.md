# Bitwarden/Vaultwarden 规格复核与覆盖矩阵

日期：2026-11-13。结论：需要修改后实施；结构检查为 0 errors，19 warnings，其中子规格路径均为待新增产物，父规格另有未生成的验收记录。

## 证据与问题（按严重程度）

1. **凭据生命周期与实际运行时不符**：需求 7.6、设计 §3.8 禁止持久化读取值，但 `apps/computer/src/native-tool-executor.ts` 的 `shell()` 创建终端日志；只对注入的 process secrets 脱敏（`apps/computer/src/runtime/tools.ts`），动态读取的密码并未自动注册。与 1Password 一致，direct read 会进入当前模型及现有会话/终端历史。调整文档承诺，不新增另一套 secret broker。
2. **秘密被 trim**：`apps/server/src/services/plugin/installations.ts` 的 `environmentValues()` 对所有 string trim。主密码前后空格必须保留。新增字段级 `preserveWhitespace`，仅 Bitwarden 主密码启用；保持现有 1Password token trim 行为。
3. **CLI 契约缺口**：设计 §3.4 表格为单行值，§3.8 为 JSON；统一为 JSON。插件变量 `BW_CLIENT_ID` / `BW_CLIENT_SECRET` 必须映射到官方 `BW_CLIENTID` / `BW_CLIENTSECRET`；解锁使用 `--passwordenv BW_MASTER_PASSWORD --raw`，会话仅通过 `BW_SESSION` 传递。CLI 自身会把认证 token 和加密 Vault 写入配置目录，必须明确临时目录例外、清理及 SIGKILL 限制，不能声称完全不落盘。
4. **站点选择冲突**：需求 5 指定 exact hostname，设计 §3.5 又允许注册域和子域回退。去除回退；网站 URL 优先完整 URI 后 exact hostname，标题查询需要显式 `--title`，多候选仅返回 metadata。读取动作只接受 UUID，不对模糊名称读取秘密。
5. **URL、公开视图和错误分类不一致**：需求 2 允许 HTTP(S)，设计仅 origin，又提路径前缀；详情有回显 server URL 与不回显的冲突。基线统一 HTTPS origin，无 userinfo、query、fragment、path（根 `/` 除外）、控制字符。所有 runtime fields 只返回 Saved/Not set。复用通用 `format: https-origin` 校验，不在 server 写 provider 分支。CLI 不提供充分信息时只报告阶段错误，不猜测“账号不存在/密码错误”。
6. **待定项没有基线**：固定 CLI 2026.10.1（官方 release 有 Linux/macOS x64/ARM64 及 SHA-256）；API Key 唯一登录方式；第一版含 TOTP；通用 runtime field 扩展；不增加状态面板。Vaultwarden 版本仅在真实实例通过后声明，未执行必须 PENDING。
7. **安全承诺边界**：只读白名单约束 wrapper 接口，普通 Shell 不能获得 Bitwarden protected fields。服务端 `BitwardenReadApproval` 绑定 bot、channel、widget、item 和恢复 run 的 approval reference；Computer 私有路径消费短时 lease 后才注入配置。普通 runtime fields 仍复用现有 process secrets；浏览器必须明确传 `secret: true`，站点反射到任意页面文本不承诺全局清除。
