# 移动端网络出口实现边界

日期：2026-11-14

## 当前决定

Spec 006.1 第一阶段实现 Android 和 iOS 的移动端 `device` Provider。移动端只接收服务端通过认证 device channel 转发的公共 TCP 请求，并通过当前移动网络建立目标连接。

共享代码放在 `mobile/shared` 的 Kotlin Multiplatform common source set 中。Android 和 iOS 只实现平台 transport、socket、网络变化、凭据存储和宿主生命周期。

## 复用的服务端协议

- Protocol：`outcomego-browser-network.v1`
- Lease：6 秒
- Renewal target：2 秒
- Stream limit：64
- Window：128 KiB，支持协商到 256 KiB
- Single data frame：64 KiB
- Total queue：16 MiB
- Device endpoint：`/api/v0/machines/channel/browser-network`
- Enrollment：`/api/v0/machines/enroll`
- Connection：`/api/v0/machines/channel/connect`
- Deployment identity：`/api/v0/machines/channel/browser-network-identity`

## Android 边界

Android 第一阶段提供用户主动开启的 Foreground Service。Service 持有 provider engine，不依赖 Activity 存活；通知提供当前状态和停止共享操作。

必须验证：

- API 34 真机上的 enrollment、lease 和公共 TCP。
- API 35 或更新系统上的 foreground service type 和运行限制。
- Wi-Fi、移动网络、VPN、断网恢复和 Doze/省电行为。
- service stop、logout、revoke、process destroy 后的清理。

## iOS 边界

iOS 第一阶段只支持 active scene 前台 Provider。scene 进入 inactive/background 后停止续租并关闭 provider channel；回到 active 后重新 enrollment 或 reconnect。

必须验证：

- Kotlin/Native framework 被现有 Swift app 正确调用。
- WebSocket、TCP dialer 和 Network path callback 的线程边界。
- active scene 内公共 TCP、DNS 拒绝和 route epoch fence。
- 进入 background 后不伪造 ready；回到 active 后恢复。

长期后台 provider、Network Extension、App Proxy、Packet Tunnel 和 App Store entitlement 不在本 Spec 实现范围内。

## 安全边界

移动端不开放监听端口，不访问手机本地文件，不读取浏览器 cookies，不允许私有/局域网/metadata 目标，不支持 UDP 或 ICMP。所有目标必须经过 hostname 规范化、DNS 全结果校验和 route epoch 校验。

## 与 Spec 006 的关系

Spec 006 原先只记录移动端可行性评估。Spec 006.1 将该评估收敛为前台 Provider 实现范围，但没有把移动端长期后台能力标记为已支持。Spec 006 的 Windows 和电脑操作界面任务继续独立推进。
